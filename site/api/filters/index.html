    Filters API — where= Parameter¶

    A where= filter restricts which records take part, by the values of other variables. It is accepted by load() and for_each(). For task usage see Filtering & Selection.

    Variable-value filters¶

    Comparing a BaseVariable subclass to a value builds a filter (no data is fetched yet):

    Side == "L"      # variable equals a value
Speed > 1.2
StartFoot != "A"

    Supported operators: ==, !=, <, <=, >, >=. The result records the variable, the operator, and the value.

    left = StepLength.load(where=Side == "L")

    left = StepLength().load(where=Side() == "L");

    Column filters¶

    For a table-valued variable, index a column and compare it:

    GaitData["side"] == "L"
GaitData["speed"] >= 1.5

    The same column expression also drives column selection in for_each inputs.

    Composition: & | ~¶

    Filters are first-class values — name them and combine them:

    clean = StepLength != 0
unilateral = (Side == "L") | (Side == "R")

StepLength.load(where=clean & (Speed > 1.2))
StepLength.load(where=~(Side == "L"))
for_each(analyze, inputs={"x": StepLength}, outputs=[Result],
         where=clean & unilateral, subject=[], session=[])
    Operator Meaning
    & and
    | or
    ~ not

    MATLAB: & / |, never && / ||

    Composition relies on operator overloading, which MATLAB allows only for the element-wise & / |. The short-circuit && / || raise "Conversion to logical from scidb.Filter is not possible". Always parenthesize: (Side() == "L") & (Speed() > 1.2).

    Helpers¶

    from scidb import raw_sql, schema_key
    • schema_key(...) — filter directly on a dataset schema key.
    • raw_sql(...) — a raw SQL predicate for expressions the filter objects can't represent.

    Use these only when the comparison syntax above isn't enough.

    Where filters apply¶

    Call Effect of where=
    Var.load(where=...) restrict which records load
    for_each(..., where=...) restrict which records the iteration processes

    For permanent, persisted exclusions across all analyses, use exclude_schema(...) instead — see Filtering & Selection and Database.
